# 拾影网页版开发交接

仓库：https://github.com/W-cola/shiying ，入口分支 `main`。

本项目已有 Windows 桌面版和原生 Android v1.7.0。根目录 Python 代码是桌面应用，不是已经可部署的前后端网站。`android/tools/preview.html` 与 `preview_server.py` 只用于本机操控安卓模拟器，不能作为公网产品部署。

## 可以复用的代码

`clipharbor.engine.Engine(data_dir, log, progress, cancel)` 是与界面解耦的入口：

```python
from pathlib import Path
from threading import Event
from clipharbor.engine import Engine

engine = Engine(Path('private-job-data'), cancel=Event())
info = engine.resolve(share_text)
result = engine.download(info, info.formats[0], Path('private-job-files'))
# 音频：engine.extract_audio(info, info.formats[0], output_dir)
```

`info.kind` 区分 `video` 和 `images`，`info.formats` 包含实际媒体来源，`info.images` 保留图片顺序。单视频返回 `Path`；图文和音频返回 `SavedMedia`，其中 `path` 为主文件或组目录，`files` 为本次产生的全部文件。

不要把 `info.raw`、带签名的媒体 URL、请求头、Cookie 或服务器本地文件路径直接序列化给网页。向客户端返回不透明的任务/素材编号和最少必要的标题、作者、画质、张数信息。

## 网页版应增加的层

1. 网页界面：链接输入、任务进度、画质和图片选择、视频/音频播放器、图文组预览、搜索及分类。
2. 后端任务服务：解析、下载、音视频整理、取消、失败重试、文件过期清理。同步网络和 FFmpeg 处理应放在后台任务中，避免阻塞 Web 请求。
3. 文件交付：后端用任务 ID 暴露所选媒体，图文可打包 ZIP；网页下载写入的是访客电脑，后端的保存文件夹属于服务器。
4. 数据和部署：每位用户隔离任务、文件、浏览器会话和历史，按所有权授权每个文件请求。Web 历史需数据库，不要直接把桌面 `Store` 当作多用户服务。

可设计 `POST /api/resolve`、`POST /api/jobs`、`GET /api/jobs/{id}`、`POST /api/jobs/{id}/cancel` 等接口。当前仓库尚未实现这些接口。

## 部署必须适配的行为

- 浏览器跨站限制决定了解析与媒体请求通常需要后端；纯前端界面不能直接替代 requests、Playwright 与 FFmpeg。
- 桌面版浏览器辅助解析会打开本机 Edge/Chrome，Web 服务器不能把这个原生窗口交给访客。需要单独设计用户登录/验证或本地辅助流程；不得共享服务器上的登录状态。
- 网络输入须限制协议、重定向、目标地址和解析结果，阻止对内网、回环、云元数据等地址的请求。桌面版允许的本机测试直链不能原样开放到公网服务。
- 音视频任务需并发、体积、时长、磁盘和超时限制；下载后的文件通过受控的 ID 取用，不能暴露任意文件系统路径。
- 视频号 sph 使用第三方在线服务，网站仍有登录、验证码、地域与接口变化的限制。失败应展示明确原因；不要生成与后端无关的模拟解析结果。
- Windows 的文件夹、剪贴板与 Qt 播放器应替换为网页交互，安卓的相册发布和系统分享属于各终端的不同实现。

先跑通真实的「链接 → 后端解析 → 文件保存 → 页面播放/下载」，再完成视觉界面。小红书真实链接可能要求登录或有效分享参数，数据样本测试不表示所有真实链接都能匿名解析。
